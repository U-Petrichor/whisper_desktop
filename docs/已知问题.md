# 已知问题

## 1. 收到的消息以明文存储在本地数据库

**严重程度：高**

Signal 协议仅保护传输层（端到端加密），两端本地持有明文。当前代码在 Signal 解密后，将 `encrypted` 标志设为 `false`，导致 `addMessage()` 跳过加密，明文直接写入 SQLite 数据库。

**涉及文件：**
- `src/services/hybridmessaging.ts` — `handleServerMessage()` 解密后将 `encrypted` 设为 `false`（约 L1072）
- `src/client_db/database.ts` — `addMessage()` 仅在 `encrypted=true` 时加密（约 L495-497）

**具体问题：**

1. **收到的消息明文存储**：`localMessageService.receiveMessage()` 传入的消息 `encrypted` 始终为 `false`，`addMessage()` 直接将明文内容写入 `messages` 表
2. **发送消息的加密形同虚设**：虽然 `addMessage()` 用用户的 `privateKey` 做 AES 加密，但 `privateKey` 本身明文存储在同一数据库的 `user_keys` 表中，任何能访问数据库文件的人都能解密
3. **双重加密冗余**：`localMessageService.sendMessage()` 用随机 AES-256-CBC 密钥加密内容，但 key/iv 未持久化到数据库；随后 `addMessage()` 又用 `privateKey` 再加密一次，第一层加密无意义
4. **P2P 消息完全未加密存储**：P2P 路径的消息 `encrypted` 标志始终为 `false`，同样是明文存储
5. **消息双重写入**：`handleServerMessage()` 和 `hybrid-store.ts` 都调用了 `localMessageService.receiveMessage()`，同一消息被写入数据库两次

**修复方向：** 引入独立的本地加密密钥（如用户密码派生的密钥，或操作系统密钥链存储的密钥），对所有存入数据库的消息内容进行 at-rest encryption，与 Signal 传输加密密钥完全分离。
